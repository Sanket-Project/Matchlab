How the predictions work
TRANSPARENT BY DESIGN

Know what is behind
every number.

Statistical forecasts run on your machine. Cricket summaries use OpenRouter with the fixture and relevant archive evidence.

01

Choose your sport

Football, cricket, tennis, badminton, baseball, and rugby each have their own score units and player threat definition. Keep different leagues, formats, and scoring conventions in separate datasets.

02

Frozen local models

TabICLv2 uses causal historical examples for opponent-adjusted outcomes, scores and interaction rates. Its official fit() prepares context without updating pretrained weights. Chronos-Bolt Small forecasts scoring form separately. Both run on CPU with local weights and automatic downloads disabled.

03

Set the information cutoff

Every historical example uses only information available before that match. Results dated on or after the query cutoff are excluded. Tennis results become available conservatively 14 days after tournament start. Missing player or interaction data produces an unavailable state.

Reference estimates are historical arithmetic

When explicitly enabled, the reference team score is 55% recent scoring average + 30% opponent's recent conceded average + 15% head-to-head scoring average. Without meetings, the final 15% uses recent form.

Winner reference shares pool the selected side's wins with the opponent's losses, add one pseudocount to each allowed outcome, and normalize. They are not calibrated win probabilities. Player scores use 75% recent average + 25% average against that opponent (recent average if absent). Player threat uses direct successes divided by opportunities.

A configured model that fails never falls back to reference estimates. Every output identifies its source. Historical score ranges describe observed results, not prediction intervals. Assess real forecast accuracy on held-out historical data before relying on a model.

Bring your data

Each sport uses matches.csv, optional players.csv, and optional interactions.csv in one local folder. Exact column definitions and configuration examples are included in the project's README.md. Singles competitors use the team/opponent columns as their two match sides.

Local dates use YYYY-MM-DD. The match outcome is explicit, so a win is never inferred from an inappropriate score aggregate. Tennis uses sets, badminton uses games, and continuous predictions represent expected scores.
